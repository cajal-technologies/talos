# Public specifications

A public specification describes values and properties, not the WebAssembly
calling convention used to transport them. New exported-operation specs use
four names; existing machine-level specs can migrate to this surface without
strengthening a partial proof into a termination claim:

```lean
structure Input where
  -- the semantic inputs of this operation

abbrev Output := -- the semantic result type

def args (input : Input) : ExportCall HostState :=
  -- initial store, host state, and raw Wasm arguments

def result (output : Output) : ExportReturn HostState → Prop :=
  -- how the semantic output is observed in a raw return
```

`args` and `result` are handwritten because a crate's serialization, memory
layout, host state, and failure convention are part of its interface. They are
not generated by Talos.

## Total normal return

For an operation proved to terminate normally on every input in its stated
domain, use this shape:

```lean
abbrev Runs := Universal.RunsExport «module»

def OperationSpec : Prop :=
  ∀ input : Input,
    ∃ output : Output,
      Runs "operation" (args input) (result output) ∧
      output = referenceImplementation input
```

The final conjunct is the mathematical claim and stays explicit in the public
statement. A named helper may support its proof, but should not make a reader
open another declaration to learn what the operation promises.

A domain restriction belongs immediately after the input:

```lean
∀ input : Input, Valid input →
  ∃ output : Output,
    Runs "operation" (args input) (result output) ∧
    output = referenceImplementation input
```

## Partial correctness

Do not add an existential run when only partial correctness has been proved.
Also do not quantify a semantic output only outside `Runs`:

```lean
∀ input output, Runs "operation" (args input) (result output) → Post input output
```

That statement can miss a real raw return if `result` recognizes no semantic
output for it. Instead require every successful raw return to decode:

```lean
@[spec_of "rust-exported-partial" "crate::operation"]
def OperationSpec : Prop :=
  ∀ input : Input,
    Universal.PartiallyRunsExport «module» "operation" (args input)
      (fun returned =>
        ∃ output : Output,
          result output returned ∧
          Post input output)
```

The `rust-exported-partial` reference kind keeps this proved safety result
visible without counting it as total-correctness coverage.

This makes no termination claim and cannot discard an inconvenient return by
leaving it outside the image of `result`.

## Traps and other terminal outcomes

When a legitimate result may be a structural trap, define a semantic sum type
such as `success value | outOfMemory` and use `RunsExportOutcome`. The
operation's `result` predicate must distinguish normal returns from traps and
inspect any relevant final host or memory state. The public property should say
explicitly which semantic outcomes are permitted.

## Crate properties

A property involving several operations contains several literal executions.
Do not create a wrapper that the crate does not have merely to make the
statement contain one run:

```lean
@[spec_of "crate-property" "hex::roundtrip",
  spec_of "rust-exported" "hex::encode",
  spec_of "rust-exported" "hex::decode"]
def RoundTripSpec : Prop :=
  ∀ input encoded decoded,
    Runs "encode" (Encode.args input) (Encode.result encoded) →
    Runs "decode" (Decode.args encoded) (Decode.result decoded) →
    decoded = input
```

The `crate-property` reference gives the property its own stable key. The
additional `rust-exported` references record every real operation involved.

## What remains below this surface

Proofs may freely use `SmallStep.Config`, raw `Value` lists, Iris resources,
linear-memory invariants, fuel witnesses, or generated function indices. Those
details belong in adapters and proofs. The `@[spec_of] def` is the product a
reader reviews, so its vocabulary is semantic `Input`, `Output`, the literal
export name, and the mathematical property.
